**이론 근거** — [Music Theory for Programmers](https://runjs.app/blog/music-theory-for-programmers)

## 1. 측정 결과

### 1.1 기본 정보

| 항목 | 값 |
|---|---|
| 길이 | 139.96초 (2:20) |
| 원본 | MP3 48kHz 스테레오, 176kbps |
| 피크 / RMS | 0.770 / 0.1016 |
| 분석 해상도 | 22.05kHz 모노, STFT hop 11.6ms |

### 1.2 템포 — **90 BPM 확정** ✅

스펙트럴 플럭스 자기상관 결과 최고점이 **179.75 BPM**입니다. 이건 89.875의 정확히 2배값이고,
86–94 구간 최고점은 **90.25 BPM**이었습니다. 말씀하신 90 BPM이 맞습니다.

```
전체 139.96초 ÷ 마디 2.6667초 = 52.49마디  → 유효 52마디
```

| 단위 | 초 |
|---|---|
| 1마디 (4/4) | 2.6667 |
| 4분음표 | 0.6667 |
| 8분음표 | 0.3333 |
| **점8분 (×1.5)** | **0.5000** |
| 16분음표 | 0.1667 |
| 3연음 | 0.2222 |

> 원문의 유일한 리듬 공식이 `beat = 60 / BPM`입니다. 90 BPM에서 **점8분이 정확히 0.5초**로
> 떨어지는 건 우연히 좋은 숫자입니다 — 딜레이 타임을 500ms로 잡으면 그대로 점8분 딜레이가 됩니다.

### 1.3 구조 — 발화 밀도 90% ⚠️ **가장 중요한 제약**

0.35초 이상 비는 구간이 **전체에서 4곳뿐**입니다.

| 구간 | 시각 | 마디 | 길이 |
|---|---|---|---|
| 인트로 공백 | 0.00 – 8.68s | 0 – 3.25 | 13.0박 |
| 짧은 숨 | 129.14 – 129.82s | 48.43 – 48.68 | 1.0박 |
| 짧은 숨 | 134.48 – 135.16s | 50.43 – 50.69 | 1.0박 |
| 아웃트로 | 135.96 – 139.92s | 50.99 – 52.47 | 5.9박 |

마디별 에너지를 4마디 블록으로 묶으면:

```
블록 0  마디  0- 3   0.15  ████                      ← 비어 있음
블록 1  마디  4- 7   0.54  █████████████████████
블록 2  마디  8-11   0.88  ███████████████████████████████████
블록 3~11 마디 12-47  0.79~0.93   ← 거의 평탄
블록12  마디 48-51   0.47  ██████████████████        ← 마무리
```

**벌스/훅 구분이 없습니다.** 8마디부터 47마디까지 밀도가 0.79~0.93으로 평탄하고,
중간에 쉬는 곳이 사실상 없습니다.

> ### ⚠️ 여기서 나오는 결론이 이 문서 전체를 지배합니다
> **아카펠라가 곡의 구조를 만들어 주지 않습니다. 비트가 전부 만들어야 합니다.**
> 그리고 랩이 90% 시간 동안 중역을 채우고 있으므로 **비트는 반드시 성겨야 합니다.**
> 꽉 찬 비트를 깔면 둘 다 죽습니다.

### 1.4 플로우 위치 — 16분 격자에 고르게 분산 ⚠️ 신뢰도 낮음

4분박을 16분 4칸으로 나눠 온셋 에너지를 집계한 결과:

```
1 (정박)   25.9%
e (16분)   24.5%
& (8분)    25.9%
a (16분)   23.7%
```

거의 완전히 균등합니다. 다만 **16분 격자 정렬도가 0.048**(1=완벽, 0=무작위)로 매우 낮습니다.
말소리는 드럼 같은 뚜렷한 트랜지언트가 없어서 스펙트럴 플럭스로는 잘 안 잡힙니다.

**그래도 읽어낼 수 있는 것:** 특정 칸에 몰리지 않는다 = 음절이 16분 격자 전역에 깔린다
= **밀도 높은 16분 플로우**. 정박에 몰리는 느린 플로우가 아닙니다.

### 1.5 주파수 점유 — **저역이 통째로 비어 있음** ✅ 이게 기회입니다

| 대역 | 에너지 비중 |
|---|---|
| 20–80 Hz | **0.1%** |
| 80–200 Hz | **0.2%** |
| 200–500 Hz | 13.6% |
| **500–1.2 kHz** | **50.3%** ← 보컬 핵심 |
| 1.2–3 kHz | 18.0% |
| 3–6 kHz | 12.5% |
| 6 kHz+ | 5.2% |

200Hz 이하가 **합쳐서 0.3%** — 이 아카펠라는 200~250Hz 부근에서 하이패스된 보컬 스템입니다.
즉 **베이스 영역에 경쟁자가 없습니다.** 서브를 마음껏 써도 충돌이 0입니다.

반대로 **500Hz–1.2kHz에 에너지의 절반**이 몰려 있습니다. 여기가 전쟁터입니다.

### 1.6 조성 — **판정 불가** ❌ 반드시 귀로 확인

두 가지 방법이 서로 다른 답을 냈습니다.

| 방법 | 결과 |
|---|---|
| 자기상관 (60–500Hz) | 중앙 294Hz = **D4** |
| 스펙트럼 배음 간격 | 중앙 201Hz = **G3** |

불일치의 원인은 명확합니다. **파일이 하이패스되어 기본주파수가 잘려 나갔습니다**
(100–150Hz 평균 진폭 0.00014 vs 250–300Hz 0.00382, 약 27배 차이).
기음이 없는 상태에서 자기상관은 배음을 기음으로 오인하기 쉽습니다.

참고로 Krumhansl 프로파일 상관은 이렇게 나왔습니다:

```
D  minor  +0.397   ← 1위지만 상관계수가 약함
C# minor  +0.300
C# major  +0.236
```

f0 피치클래스도 D(23.6%)와 C#(21.9%)이 반음 차이로 붙어 있어 깨끗한 판정이 아닙니다.

> **랩은 원래 조성이 약합니다.** 노래가 아니라 말이므로 확정된 조가 없는 게 정상이고,
> 그래서 **비트가 조를 정하면 보컬이 따라옵니다.** 아래 §3이 이 문제의 해법입니다.

## 2. 원문에서 가져올 것

이 곡에 직접 쓸 수 있는 항목만 추렸습니다.

| 원문 요소 | 이 곡에서의 쓸모 |
|---|---|
| `beat = 60 / BPM` | 90 BPM 격자 전체의 출발점 |
| **단5음 `[3,2,2,3,2]`** | *"두 음을 뺀다. 그래서 틀린 음을 짚기가 그토록 어렵다"* → **조성 불확실성의 보험** |
| 블루스 `[3,2,1,1,3,2]` | *"의도적으로 어색한 음 하나"* → 훅 포인트용, 아껴 쓸 것 |
| 자연단조 `[2,1,2,2,1,2,2]` | 코드용 기본 스케일 |
| 코드 = 스케일 위 `[0,2,4]` | 3화음. `[0,2,4,6]`이면 7화음 |
| m7 `[0,3,7,10]` | *"우수에 찬"* — 90 BPM 힙합의 기본 색 |
| 로마숫자 = 상대 주소 | **조가 틀렸을 때 `.map(n => n + k)` 한 줄로 전조** |
| 점 = 1.5배 | 점8분 = 0.5초 = 딜레이 타임 |
| *"같은 여섯 음을 셋/둘로 묶으면 다른 곡"* | 2마디 변주로 52마디를 버티게 하는 장치 |
| 배음렬 / 파형 | 음역별 파형 선택 (§4) |
| 보이스 리딩 | *"가장 짧은 거리로"* — 다만 그루브 음악에선 주의 (§5) |

원문 저자 본인의 고백도 참고할 만합니다 — *"리듬은 거의 다루지 못했고, 읽어 본 바로는
보기보다 훨씬 깊다."* 이 곡에서 어려운 부분은 정확히 그 리듬 쪽입니다.

## 3. 조성 전략 — 모르는 걸 모르는 채로 다루기

조를 특정할 수 없다는 게 이 프로젝트의 핵심 리스크입니다. 세 단계로 처리합니다.

### 3.1 1단계 — 5음 음계로 시작한다 (보험)

> 원문: *"5음 음계는 두 음을 뺀다. 그래서 틀린 음을 짚기가 그토록 어렵고,
> 모든 초보 기타 강습이 거기서 시작한다."*

**빠진 두 음이 정확히 충돌 위험이 큰 음(2도와 6도)입니다.** 조가 애매한 보컬 위에
5음 음계로 만든 리프를 얹으면 틀릴 확률이 구조적으로 낮습니다.

```javascript
const PENTA = [3, 2, 2, 3, 2];              // 원문 발췌, 합 12
const scale = build(root, PENTA).slice(0, 5);
```

### 3.2 2단계 — D단조로 걸고 귀로 검증한다 ※ 미확인

측정이 약하게나마 가리키는 곳이 D단조(+0.397)입니다. 여기서 출발하되 **검증 절차를 반드시 거칩니다.**

**검증 방법 (5분이면 됩니다):**
1. 아카펠라를 틀고 그 위에 **루트 음 하나만** 길게 깝니다 (D2, 73.4Hz).
2. 어색하면 반음씩 올리며 12개를 다 시도합니다. 편안한 음이 루트입니다.
3. 루트가 정해지면 그 위에 **5도**(루트+7반음)를 더합니다. 여전히 괜찮으면 확정.
4. 마지막에 **3도**를 넣어 장/단을 정합니다 — 단3도(+3)가 편하면 단조, 장3도(+4)면 장조.

3도를 마지막에 넣는 이유는 원문에 있습니다 — 장3화음 `[0,4,7]`과 단3화음 `[0,3,7]`은
**반음 하나 차이인데 감정이 완전히 다릅니다.** 루트·5도는 조성에 중립적이라 먼저 걸어도 안전합니다.

### 3.3 3단계 — 틀렸으면 상수 덧셈으로 옮긴다

> 원문: *"로마숫자는 상대 주소 지정 — 조를 옮기는 것은 상수 덧셈일 뿐이다."*

비트를 음도(degree)로 짜 두면 조가 틀렸을 때 전체를 한 줄로 이동시킬 수 있습니다.

```javascript
const KEY = 50;                 // D3. 틀렸다고 판명되면 이 숫자 하나만 바꾼다
const chord = (deg) => [0,2,4].map(s => { ... });   // 조와 무관하게 동작
```

**절대 하지 말 것:** 주파수나 MIDI 번호를 하드코딩하는 것. 조를 바꿀 때 전부 다시 써야 합니다.

## 4. 주파수 배치 — 측정에서 바로 나오는 설계

§1.5의 대역 점유를 그대로 뒤집으면 배치도가 됩니다.

```
        아카펠라                        비트가 들어갈 자리
20-200Hz    0.3%  ░░░░░░░░░░░░░░░░  ██████████████  서브·킥 (충돌 0)
200-500Hz  13.6%  ████░░░░░░░░░░░░  ██████████      코드·패드 (조심)
500-1.2k   50.3%  ████████████████  ░░              ← 지속음 금지
1.2-3k     18.0%  ██████░░░░░░░░░░  ████            스네어 몸통
3k+        17.7%  █████░░░░░░░░░░░  ██████          하이햇·에어
```

| 파트 | MIDI | Hz | 근거 |
|---|---|---|---|
| 서브베이스 | 24–40 | 33–82 | 아카펠라 저역이 완전히 비어 있음 |
| 코드/패드 | 50–69 | 147–440 | 보컬 핵심대역(500Hz) 아래 |
| 리드 | 72–84 | 523–1047 | **핵심대역 정면 — 짧은 음만, 지속 금지** |
| 하이햇 | — | 6k+ | 보컬 상단이 5.2%뿐 |

**핵심 규칙 세 가지**

1. **500Hz–1.2kHz에 지속음을 두지 않는다.** 패드·스트링·서스테인 리드가 여기 있으면
   랩이 묻힙니다. 이 대역에는 **짧은 음(플럭·스탭)만** 놓습니다.
2. **코드는 147–440Hz(D3–A4)에 앉힌다.** 보컬 아래에서 화성만 지탱합니다.
3. **베이스는 마음껏.** 이 아카펠라는 200Hz 이하가 통째로 비어 있어
   서브가 아무리 커도 랩을 가리지 않습니다. **이 곡에서 가장 큰 무기입니다.**

> 이전에 EDM Lab에서 겪은 문제(저역 사인만 있으면 "웅" 소리로만 들림)가 여기서도
> 똑같이 적용됩니다. 서브에 배음 레이어를 병렬로 섞어 작은 스피커에서도 음정이
> 전달되게 해야 합니다.

## 5. 리듬 전략

### 5.1 하프타임으로 간다

랩이 16분 격자에 빽빽하므로(§1.4) **드럼이 같이 빽빽하면 서로를 지웁니다.**

```
킥      1박  (+ 3.5박 고스트)
스네어  3박
하이햇  8분, 16분은 4마디에 한 번만
```

90 BPM 하프타임은 체감상 45 BPM의 여유를 주면서 랩의 16분은 그대로 살아 있게 합니다.
4-on-the-floor는 이 소재에 **절대 쓰면 안 됩니다** — 정박마다 킥이 들어가면
랩의 리듬적 자유가 전부 죽습니다.

### 5.2 점8분 = 0.5초를 쓴다

원문의 *"점은 길이를 1.5배로 만든다"* → 90 BPM에서 점8분이 **정확히 0.500초**입니다.

- 리드/스탭 딜레이를 500ms로 잡으면 그대로 점8분 딜레이
- `LCM(3, 16) = 48` → 3마디마다 정박 복귀. 4마디 코드 루프와 겹치면 **12마디 대순환**
- 랩이 이미 16분을 채우고 있으므로 이 레이어는 **아주 작게**(-18dB 수준) 깔 것

### 5.3 빈 곳에만 필을 넣는다

§1.3에서 찾은 공백은 4곳뿐입니다. 필·리버스·라이저는 **여기에만** 넣습니다.

| 마디 | 길이 | 용도 |
|---|---|---|
| 0 – 3.25 | 13박 | 인트로. 비트 단독으로 곡을 여는 유일한 기회 |
| 48.43 / 50.43 | 각 1박 | 짧은 스네어 롤 정도 |
| 51 – 52.5 | 6박 | 아웃트로. 여기서 끝내거나 태그 |

그 외 구간에 필을 넣으면 랩과 정면 충돌합니다.

## 6. 구조 설계 — 비트가 서사를 만든다

아카펠라가 평탄하므로(§1.3) 8마디 단위로 **비트 쪽에서** 기승전결을 만듭니다.

| 마디 | 구간 | 비트 |
|---|---|---|
| 0–3 | 인트로 | 랩 없음. 코드 + 필터된 드럼만 |
| 4–7 | 진입 | 랩 시작(밀도 0.54). 킥·서브 합류 |
| 8–23 | 벌스 A | 풀 비트. 여기가 기준점 |
| 24–31 | 변화 1 | 코드 보이싱만 바꾸거나 스탭 음색 교체 |
| 32–39 | 변화 2 | 카운터 멜로디 추가 (짧은 음으로) |
| 40–47 | 절정 | 밀도 최고(0.93) 구간. 레이어 최대 |
| 48–52 | 마무리 | 요소를 하나씩 뺀다 |

**52마디를 지루하지 않게 버티는 장치** — 원문의 그 문장을 씁니다.

> *"같은 여섯 음을 셋씩 묶어 연주하는 것과 둘씩 묶어 연주하는 것은 서로 다른 곡이 된다."*

음을 바꾸지 않고 **묶음만 바꿉니다.** 벌스 A는 2로, 변화 1은 3으로 묶으면
같은 재료가 다른 곡처럼 들립니다. 새 멜로디를 쓰는 것보다 안전하고
(조성 리스크가 없고) 랩과의 충돌도 늘지 않습니다.

## 7. 음색 설계

원문의 배음 이론을 음역별로 적용합니다.

| 파트 | 파형 | 근거 |
|---|---|---|
| 서브 | 사인 + 병렬 새추레이션 | 사인 = 단일 주파수. 배음이 없으면 작은 스피커에서 안 들림 |
| 베이스 배음층 | tanh 새추레이션 → BP 700Hz | 홀수 배음 생성. 저역 증가 없이 음정만 전달 |
| 코드 | 삼각파 / 로즈(배음 1·2·4) | 톱니는 배음이 너무 많아 보컬 대역을 침범 |
| 스탭 | 사각파 | *"홀수 배음만 — 텅 빈 소리"*. 톱니보다 좁아 랩 사이를 뚫고 나옴 |
| 하이햇 | 노이즈 + HP 8kHz | 보컬 6kHz+ 가 5.2%뿐이라 안전 |

**ADSR** — 원문의 네 단계 중 이 곡에서 중요한 건 **릴리즈**입니다.
릴리즈가 길면 소리가 겹쳐 500Hz–1.2kHz를 채워 버립니다. 코드 릴리즈는 짧게,
공간감은 리버브가 아니라 **딜레이**로 만드는 게 안전합니다
(리버브는 대역 전체를 뿌옇게 만들지만 딜레이는 리듬 안에 숨습니다).

## 8. 실행 순서

1. **격자부터 맞춘다** — 90 BPM, 아카펠라를 0초에 놓으면 랩은 8.68초(마디 3.25)부터 시작.
   유효 52마디.
2. **§3.2 루트 검증** — 이게 먼저입니다. 조를 틀리면 나머지가 전부 무의미합니다.
   D2부터 시작해 12개를 다 시도할 것. ※ 이 단계는 제가 대신 못 합니다.
3. **드럼 골격** — 하프타임 킥/스네어만. 이 상태로 아카펠라와 함께 들어 봅니다.
4. **서브 베이스** — 충돌이 0인 영역이므로 여기서 곡의 무게를 다 만듭니다.
5. **코드** — 147–440Hz, m7 `[0,3,7,10]`, 5음 기반 리프.
6. **스탭/리드** — 짧은 음만. 절대 지속시키지 않습니다.
7. **구간 편집** — §6 표대로 8마디마다 하나씩 바꿉니다.
8. **필** — §5.3의 4곳에만.

## 9. 검증 체크리스트

| 확인 | 방법 |
|---|---|
| 조가 맞는가 | 루트만 깔고 12반음 전부 시도 (§3.2) — **필수** |
| 랩이 묻히지 않는가 | 500Hz–1.2kHz에 지속음이 있는지 확인 |
| 비트가 너무 빽빽한가 | 드럼만 빼고 들어 보기. 랩이 답답하면 16분 요소를 줄인다 |
| 베이스가 웅 거리는가 | 배음 레이어 비율을 올린다 |
| 52마디가 지루한가 | 새 멜로디 대신 **묶음 변경**(§6)을 먼저 시도 |
