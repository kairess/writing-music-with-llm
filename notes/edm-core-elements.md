# 멜로딕 프로그레시브 하우스 EDM 작곡을 위한 핵심 요소

> 출처: [Music Theory for Programmers — runjs.app](https://runjs.app/blog/music-theory-for-programmers)
> 위 글은 특정 장르를 다루지 않는 "코드로 배우는 음악 이론" 글입니다.
> 다만 글의 최종 예제(A 단조 / 104 BPM / `[1, 6, 3, 7]` 진행)가 사실상 멜로딕 하우스 루프 그 자체이므로,
> 그 예제를 중심으로 이 사운드에 직결되는 요소만 발췌·번역했습니다.
> `※ 보강` 표시가 붙은 항목은 원문에 없는, 맥락을 위해 추가한 설명입니다.

---

## 0. 한 줄 요약

원문의 마지막 예제 코드가 곧 정답입니다.

```javascript
const key = 57;                                        // A
const scale = build(key, [2, 1, 2, 2, 1, 2, 2]).slice(0, 7);  // A 자연단음계
const bpm = 104;
const progression = [1, 6, 3, 7];                      // i – VI – III – VII
const melody = [0, 2, 4, 2, 3, 2, 1, 0, 4, 3, 2, 1, 0, 2, 1, 0];
```

**단조 스케일 + i–VI–III–VII 진행 + 스케일 음도(degree)로만 만든 단순 반복 멜로디.**
이것이 "슬픈데 신나는" 느낌의 뼈대입니다.

---

## 1. 조성(Key): 자연단음계(Natural Minor)

원문 발췌:

- 장음계 패턴: `[2, 2, 1, 2, 2, 2, 1]` (반음 간격, 합계 12)
- **자연단음계 패턴: `[2, 1, 2, 2, 1, 2, 2]`**
- 핵심 통찰: *"음악은 12음 중 부분집합을 고른다 — 간격이 고르지 않도록 고른다."*
  간격이 균등하면 방향 감각이 사라져 "어긋난" 소리가 납니다.

원문 예제는 MIDI 57(A)을 루트로 잡습니다. 결과 스케일:

| 음도 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 음이름 | A | B | C | D | E | F | G |
| MIDI | 57 | 59 | 60 | 62 | 64 | 65 | 67 |

> **왜 단조인가 (※ 보강)** — 이 계열의 곡은 대부분 단조입니다. 멜랑콜리한 화성 위에
> 밝은 신스 음색과 4-on-the-floor 드럼을 얹는 대비가 그 사운드의 정체성입니다.

### 관련: 모드는 배열 회전일 뿐

원문은 7개 교회선법을 "장음계 패턴 배열의 회전"으로 정의합니다.

1. Ionian (장조): `[2, 2, 1, 2, 2, 2, 1]`
2. Dorian: `[2, 1, 2, 2, 2, 1, 2]`
3. Phrygian: `[1, 2, 2, 2, 1, 2, 2]`
4. Lydian: `[2, 2, 2, 1, 2, 2, 1]`
5. Mixolydian: `[2, 2, 1, 2, 2, 1, 2]`
6. **Aeolian (자연단조): `[2, 1, 2, 2, 1, 2, 2]`**
7. Locrian: `[1, 2, 2, 1, 2, 2, 2]`

> 변주를 주고 싶다면 Dorian(6음이 반음 높음)이 가장 안전합니다. 단조의 어두움을 유지하면서
> 살짝 밝아집니다. (※ 보강)

### 멜로디용 5음 음계

원문 발췌:

- 장5음음계: `[2, 2, 3, 2, 3]`
- **단5음음계: `[3, 2, 2, 3, 2]`**
- 블루스: `[3, 2, 1, 1, 3, 2]`

> 이 장르의 훅(특히 기타/피아노/브라스 리드)은 5음 음계 안에서 움직이는 경우가 많습니다.
> 반음이 없어 어떤 코드 위에 올려도 틀리지 않습니다. (※ 보강)

## 2. 코드 진행: i – VI – III – VII

원문 예제의 `progression = [1, 6, 3, 7]`을 A 단조에서 전개하면:

| 순서 | 음도 | 코드 | 구성음 (MIDI) | 구성음 |
|---|---|---|---|---|
| 1 | i | **Am** | 57, 60, 64 | A – C – E |
| 2 | VI | **F** | 65, 69, 72 | F – A – C |
| 3 | III | **C** | 60, 64, 67 | C – E – G |
| 4 | VII | **G** | 67, 71, 74 | G – B – D |

원문의 코드 생성 로직:

```javascript
// 스케일 위에서 한 칸 건너뛴 3개 음([0, 2, 4]) = 3화음
const chord = (degree) =>
  [0, 2, 4].map((step) => {
    const i = degree - 1 + step;
    return scale[i % 7] + Math.floor(i / 7) * 12;
  });
```

원문이 제시하는 다른 대표 진행:

- **I – V – vi – IV** — "팝/현대 팝의 표준"
- ii – V – I — 재즈의 근간
- I – vi – IV – V — 같은 네 코드의 회전
- **vi – IV – I – V** — "슬픈 버전"

> **핵심 (※ 보강)** — `vi–IV–I–V`(장조 관점)와 `i–VI–III–VII`(단조 관점)는 **같은 네 개의 코드**입니다.
> 2010년대 페스티벌 하우스 히트곡 상당수가 이 네 코드 위에 세워져 있습니다.
> 4마디 루프를 곡 전체에 그대로 돌리고, 변화는 **편곡(악기 추가/제거)** 으로만 주는 것이
> 이 장르의 문법입니다.

### 왜 이 진행이 "끝나지 않는" 느낌인가

원문 발췌:

> **I로 끝나면 완결된 느낌, V로 끝나면 계속될 것 같은 느낌, vii°로 끝나면 부서진 느낌이 난다.**

`i–VI–III–VII`는 VII(G)로 끝나 다시 i(Am)로 돌아갑니다. 해결되지 않고 계속 굴러가기 때문에
무한 반복되는 댄스 루프에 최적입니다.

## 3. 화성의 재료: 3화음과 7화음

원문 발췌 (반음 단위):

**3화음**
- **장3화음: `[0, 4, 7]`** — 주파수 비 약 4:5:6
- **단3화음: `[0, 3, 7]`** — *"반음 하나 차이로 완전히 다른 감정"*
- 감3화음: `[0, 3, 6]` — 불안한 소리
- 증3화음: `[0, 4, 8]` — 불길한 소리

**7화음**
- 메이저 7th: `[0, 4, 7, 11]` — 재즈 카페 느낌
- **마이너 7th: `[0, 3, 7, 10]` — 우수에 찬 느낌**
- 도미넌트 7th: `[0, 4, 7, 10]` — 긴장 생성기

> 이 스타일에서는 **기본 3화음을 그대로 쓰되, 서스테인이 긴 패드/피아노로 넓게 벌려**
> 배치하는 것이 일반적입니다. 감정을 더 얹고 싶은 브레이크다운 구간에서만
> 마이너 7th(`[0, 3, 7, 10]`)를 씁니다. (※ 보강)

### 조성 안의 7개 코드는 강제된다

원문 발췌: 스케일의 각 음도 위에 3화음을 쌓으면 **장3화음 3개, 단3화음 3개, 감3화음 1개**가
필연적으로 나옵니다. C 장조 기준:

| 로마숫자 | 코드 | 반음 |
|---|---|---|
| I | C major | `[0, 4, 7]` |
| ii | D minor | `[2, 5, 9]` |
| iii | E minor | `[4, 7, 12]` |
| IV | F major | `[5, 9, 12]` |
| V | G major | `[7, 11, 14]` |
| vi | A minor | `[9, 12, 16]` |
| vii° | B diminished | `[11, 14, 17]` |

로마숫자 표기는 **조성 독립적(key-independent)** 입니다. 원문 표현으로는
*"로마숫자는 상대 주소 지정 — 조를 옮기는 것은 상수 덧셈일 뿐"*.
즉 보컬 음역에 맞춰 키를 바꿔도 진행 로직은 그대로입니다.

## 4. 긴장과 해결: 드롭 직전을 설계하는 법

원문 발췌 — 도미넌트(V)가 으뜸화음(I)으로 끌리는 두 가지 메커니즘:

1. **이끔음(leading tone)** — V의 B는 I의 근음 C보다 반음 아래에 있어 위로 끌린다.
2. **트라이톤(tritone)** — 도미넌트 7화음에 든 B와 F는 6반음(√2 비율) 간격이며,
   *"사용 가능한 가장 불안정한 음정"* 이다. 둘이 **서로 반대 방향으로 각각 반음씩** 움직여 해결된다.

원문은 트라이톤(√2)을 *"어색하고, 무리수이며, 해결되지 않은"* 음정으로 정의합니다.

> **적용 (※ 보강)** — 빌드업 마지막 1~2마디에 V(또는 V7)를 놓고 드롭 첫 박에서 i로 떨어뜨리면
> 긴장이 물리적으로 해소됩니다. 원문의 4코드 루프를 그대로 쓰되 빌드업에서만
> VII(G)를 V(E 또는 E7 = `[64, 68, 71, 74]`)로 바꾸는 것이 가장 간단한 방법입니다.

## 5. 템포와 박자

원문 발췌:

- 악보는 절대 시간(초)이 아니라 **상대 길이(박)** 를 저장한다.
- **`박(초) = 60 / BPM`**
- 같은 배열을 120 BPM과 200 BPM에서 재생하면 동일한 음악이 속도만 달라진다.
- 박자표 `X/Y` — X는 마디당 박 수, Y는 박의 기준 음표.
  - **4/4: 마디당 4분음표 4박**
  - 3/4: 마디당 4분음표 3박
- **각 그룹의 첫 박이 강박(strong beat)이다.**
- 음표 길이는 2의 거듭제곱(온음표 → 2분 → 4분 → 8분 → 16분).
  점 하나는 길이를 1.5배, 점 둘은 1.75배로 만든다.

원문 예제:

```javascript
const bpm = 104;
const beat = 60 / bpm;   // ≈ 0.577초
```

> **(※ 보강)** 원문 예제는 104 BPM이지만, 이 장르의 실제 곡은 대부분 **125–128 BPM**입니다.
> 박자는 예외 없이 **4/4**이며, 강박마다 킥이 들어가는 4-on-the-floor가 기본입니다.
> 구조도 4의 배수로 고정: 8마디 단위 프레이즈, 16마디 빌드업, 32마디 드롭.

## 6. 음색(Timbre): 신스 사운드의 물리

원문 발췌 — 배음렬은 기본 주파수의 정수배(1x, 2x, 3x, 4x, 5x…)로 생성되며,
어떤 배음을 섞느냐가 악기의 성격을 결정합니다.

| 파형 | 배음 구성 | 성격 |
|---|---|---|
| 사인(Sine) | 단일 주파수 | 순수함 |
| **톱니(Sawtooth)** | **모든 배음** | **버징(buzzy)** |
| 사각(Square) | 홀수 배음만 | 텅 빈(hollow) 느낌 |
| 삼각(Triangle) | 중간 | 중간적 |

> **적용 (※ 보강)** — 이 장르의 리드는 **톱니파를 여러 개 디튠해서 겹친 슈퍼소(supersaw)** 가
> 전형입니다. 모든 배음이 들어 있어야 두껍고 밝게 들립니다.
> 베이스는 사인/삼각파로 배음을 줄여 킥과 부딪히지 않게 합니다.

### ADSR 엔벨로프

원문 발췌:

- **Attack** — 페이드인 시간
- **Decay** — 서스테인 레벨까지 떨어지는 시간
- **Sustain** — 건반을 누르고 있는 동안 유지되는 레벨
- **Release** — 건반을 뗀 뒤 페이드아웃
- 원문 예시 값: **어택 10ms, 디케이 1.00초**

> **적용 (※ 보강)** — 플럭(pluck) 리드는 짧은 어택(≤10ms) + 짧은 디케이 + 낮은 서스테인.
> 브레이크다운의 패드는 긴 어택(200ms~) + 긴 릴리즈.
> 같은 음표 배열이라도 엔벨로프만 바꾸면 벌스/드롭의 성격이 갈립니다.

## 7. 멜로디 작법

원문 예제:

```javascript
const melody = [0, 2, 4, 2, 3, 2, 1, 0, 4, 3, 2, 1, 0, 2, 1, 0];
```

여기서 숫자는 **주파수도 MIDI 번호도 아닌 스케일 음도 인덱스**입니다.
스케일 배열의 인덱스만 쓰면 조성에서 벗어난 음이 나올 수 없습니다.

관찰되는 특징:
- 16개 음 = 4/4 기준 정확히 4마디 (마디당 4음)
- 도약보다 **순차진행(0→2→4, 4→3→2→1→0)** 이 압도적으로 많음
- **0(루트)으로 시작해 0으로 끝남** — 완결감
- 앞 8음과 뒤 8음이 유사한 윤곽 — 반복과 변형

> **(※ 보강)** 이런 훅의 특징은 **음역이 좁고, 리듬이 단순하며, 한 번 들으면 따라 부를 수 있다**는 점입니다.
> 위 배열처럼 음도 0~4 범위 안에서만 움직여도 충분합니다.
> 화려함은 멜로디가 아니라 편곡(레이어링)에서 나옵니다.

## 8. 숫자로 음을 다루기 위한 기초 (원문 핵심 공식)

### MIDI ↔ 주파수

```javascript
const midiToFreq = (n) => 440 * 2 ** ((n - 69) / 12);
```

- MIDI 69 = 440Hz = A (기준음)
- MIDI 60 = 가온다(middle C)
- MIDI 81 = 기준음보다 한 옥타브 위 A
- MIDI 번호 +1 = 반음 하나

### 왜 12음인가

원문 발췌:

- 완전5도(3/2)를 12번 쌓으면 `(3/2)^12`, 7옥타브는 `2^7`. 둘의 차이는 **1.0136배**,
  즉 **23센트**의 "피타고라스 콤마". `3^n`은 결코 `2^(n+m)`이 될 수 없기에(둘 다 소수) 이 간극은 닫히지 않는다.
- 해결책이 **평균율**: 옥타브를 12개의 균등한 곱셈 단계로 나눈다 → `2^(1/12) ≈ 1.0595`
- 그 결과 옥타브는 구조적으로 완벽하고, 완전5도(7반음)는 순정률보다 약 **2센트 낮다.**
- 5부터 25까지 분할을 전부 테스트해보면, **5도를 약 0.1% 오차로 맞추는 첫 번째 분할이 12**다.

### 왜 단순한 비율이 좋게 들리는가

| 비율 | 음정 | 성격 |
|---|---|---|
| 2/1 | 옥타브 | 가장 깨끗함 |
| 3/2 | 완전5도 | 매우 협화적 |
| 4/3 | 완전4도 | 협화적 |
| 5/4 | 장3도 | 협화적 |
| 16/15 | 반음 | 불협화 |
| √2 | 트라이톤 | 어색함, 해결되지 않음 |

원문: *"분수가 단순할수록 좋게 들린다"* — 배음이 정렬되어 맥놀이(beating) 대신 서로를 강화하기 때문.

## 9. 실전 체크리스트

| 요소 | 선택 |
|---|---|
| 조성 | 단조 (자연단음계 `[2, 1, 2, 2, 1, 2, 2]`) |
| 코드 진행 | **i – VI – III – VII** (예: Am – F – C – G), 4마디 루프 |
| 코드 종류 | 기본 3화음, 브레이크다운에서만 m7 `[0, 3, 7, 10]` |
| 템포 | 125–128 BPM (※ 원문 예제는 104) |
| 박자 | 4/4, 강박마다 킥 |
| 구조 | 8/16/32마디 단위 |
| 멜로디 | 스케일 음도 0~4 범위, 순차진행 위주, 0으로 시작·종료 |
| 리드 음색 | 디튠된 톱니파(슈퍼소) — 모든 배음 |
| 베이스 음색 | 사인/삼각파 — 배음 최소 |
| 엔벨로프 | 리드는 어택 10ms 이하의 플럭, 패드는 긴 어택·긴 릴리즈 |
| 빌드업 | 마지막 마디를 V(또는 V7)로 → 드롭 첫 박에 i로 해결 |

## 10. 바로 실행 가능한 스타터 코드

원문 코드를 페스티벌 하우스 세팅(126 BPM)으로 정리한 것입니다.

```javascript
const midiToFreq = (n) => 440 * 2 ** ((n - 69) / 12);
const build = (root, p) => p.reduce((n, s) => [...n, n.at(-1) + s], [root]);

const key = 57;                                                  // A
```
