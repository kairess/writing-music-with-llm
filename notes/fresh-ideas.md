# 더 신선한 곡을 위한 아이디어 — 원문 재분석

현재 루프(A 자연단조 / i–VI–III–VII / 4분음표 멜로디 / 4-on-the-floor)는
원문의 **극히 일부만** 쓰고 있습니다. 아래는 원문에 있으면서 **아직 한 번도 안 쓴 요소들**과,
그것을 곡에 넣는 구체적인 방법입니다. 모든 항목에 원문 근거를 붙였습니다.

현재 사용 중 / 미사용 대조표:

| 원문 섹션 | 현재 루프 | 미사용분 |
|---|---|---|
| 스케일 | 자연단조만 | 나머지 6개 모드, 5음, 블루스 |
| 화음 | 3화음만 | 7화음, 감/증화음, 9화음, 4도 쌓기 |
| 긴장과 해결 | **전혀 안 씀** | 이끔음, 트라이톤, V→i |
| 리듬 | 4분음표만 | 점음표(1.5×), 박자표 변경 |
| 배음/음색 | 톱니·삼각 고정 | 홀수배음, 배음 가산, 순정률 |
| 조성 | A단조 고정 | 전조(= 상수 덧셈) |
| 평균율 | 12-EDO 고정 | 5~25 분할, 순정률 비교 |

---

## Tier 1 — 가장 큰 변화를 만드는 셋

### 1. 이끔음: 곡에서 유일하게 "스케일 밖"을 쓰는 순간

**원문 근거** (§코드 진행과 긴장):
> V의 B는 I의 근음 C보다 반음 아래에 있어 위로 끌린다 (이끔음).
> 도미넌트 7화음의 트라이톤은 *"사용 가능한 가장 불안정한 음정"* 이다.

현재 루프는 **7개 음 안에서만** 움직입니다. 그래서 안전하지만 밋밋합니다.
A 자연단조의 7음은 G(67)인데, 이걸 **G#(68)로 반음 올리면** A(69)를 반음 아래에서 밀어 올립니다.

```javascript
// V7 = E7 — G#은 A 자연단조에 없는 음이다. 이게 핵심.
const V7 = [64, 68, 71, 74];   // E  G#  B  D
// 트라이톤: G#(68) ↔ D(74) = 6반음
// G#(68) → A(69)  반음 상행  ← 이끔음
// D (74) → C(72)  온음 하행
```

**적용법 — 8마디 프레이즈의 마지막 마디만 교체:**

```javascript
const progression = [1, 6, 3, 7];
const chordAt = (bar) =>
  (bar % 8 === 7) ? [64, 68, 71, 74]   // 8마디마다 VII(G) 대신 V7(E7)
                  : chord(progression[bar % 4]);
```

빌드업 마지막 마디를 E7으로 두고 드롭 첫 박에 Am으로 떨어뜨리면,
"드롭이 터진다"는 느낌이 **화성적으로** 만들어집니다. 지금은 필터/볼륨으로만 만들고 있죠.

> **왜 신선한가** — 4코드 루프를 무한 반복하는 곡 대부분이 이걸 안 합니다.
> 스케일 밖 음 하나가 8마디에 한 번 나오는 것만으로 귀가 다시 깨어납니다.

### 2. 점음표 폴리리듬 — 3 대 4

**원문 근거** (§길이 인코딩):
> 음표 뒤의 점은 길이를 **1.5배**로 만든다 (점 둘은 1.75배).
> 음표 길이는 2의 거듭제곱이다.

여기서 나오는 결과:

```
점8분음표 = 0.5 × 1.5 = 0.75박 = 16분음표 3개
4/4 한 마디 = 16분음표 16개
LCM(3, 16) = 48 → 3마디마다 다시 강박에 정렬
```

**2의 거듭제곱 격자 위에 3을 얹으면** 자리가 계속 어긋나면서 3마디에 한 번 맞아떨어집니다.
이게 현대 팝/EDM의 "점8분 딜레이(dotted-eighth delay)" 사운드의 정체입니다.

```javascript
// 아르페지오를 0.75박 간격으로 — 마디 경계를 계속 넘어간다
const arpNotes = chord(deg);                    // [A, C, E]
const step = beat * 0.75;                       // 점8분
for (let k = 0; k * step < beat * 4; k++) {
  pluck(arpNotes[k % 3] + 12, t0 + k * step, step);
}
```

또는 딜레이 이펙트로:

```javascript
// 리드에 0.75박 딜레이를 3탭 — 원음과 어긋나며 셔플감이 생긴다
[1, 2, 3].forEach((tap) =>
  pluck(m, t0 + tap * beat * 0.75, beat, 0.5 ** tap));
```

> **왜 신선한가** — 현재 멜로디는 마디당 정확히 4음, 완전한 정사각형입니다.
> 여기에 0.75박 레이어 하나만 얹으면 리듬의 밀도와 "굴러가는" 느낌이 즉시 생깁니다.
> 코드도 진행도 안 건드립니다.

### 3. 모드 전환 = 배열 회전 한 줄

**원문 근거** (§모드):
> 모드는 배열 회전이다. Ionian이 장조이고 Aeolian이 단조다.

```javascript
const rotate = (arr, n) => [...arr.slice(n), ...arr.slice(0, n)];
const MAJOR = [2, 2, 1, 2, 2, 2, 1];

const AEOLIAN    = rotate(MAJOR, 5);  // [2,1,2,2,1,2,2]  현재 사용 중
const DORIAN     = rotate(MAJOR, 1);  // [2,1,2,2,2,1,2]  ← 6음만 반음 높음
const MIXOLYDIAN = rotate(MAJOR, 4);  // [2,2,1,2,2,1,2]
const PHRYGIAN   = rotate(MAJOR, 2);  // [1,2,2,2,1,2,2]  ← 2음이 반음 낮음
```

**A 도리안 vs A 에올리안 — 단 한 음 차이:**

| | 1 | 2 | 3 | 4 | 5 | **6** | 7 |
|---|---|---|---|---|---|---|---|
| 에올리안 | A | B | C | D | E | **F** | G |
| 도리안 | A | B | C | D | E | **F♯** | G |

그 결과 **VI(F major)가 IV(D major)로 바뀝니다.** 어두운데 밝은, 애매한 색.

**적용법 — 섹션마다 모드를 갈아끼움:**

```javascript
const sections = [
  { bars: 8,  mode: AEOLIAN,    label: 'intro' },
  { bars: 16, mode: DORIAN,     label: 'drop'      },  // 밝아짐
  { bars: 8,  mode: PHRYGIAN,   label: 'breakdown' },  // 확 어두워짐
  { bars: 16, mode: DORIAN,     label: 'drop 2'    },
];
```

> **왜 신선한가** — 코드 진행도, 멜로디 배열도, BPM도 안 바꾸고 **스케일 배열만 회전**시키면
> 같은 재료가 완전히 다른 감정으로 들립니다. 원문의 "모드는 배열 회전" 통찰을 그대로 구조에 쓰는 것.

## Tier 2 — 음색과 튜닝 (이 부분이 진짜 차별점)

### 4. 순정률 레이어 — 평균율이 못 맞추는 그 오차를 이용

**원문 근거** (§단순한 비율이 좋게 들린다 / §평균율):
> 분수가 단순할수록 좋게 들린다 — 배음이 정렬되어 맥놀이 대신 서로를 강화하기 때문.
> 평균율은 옥타브를 구조적으로 완벽하게 만드는 대신 나머지를 근사한다.

검증한 실제 오차:

| 음정 | 평균율 | 순정률 | 차이 |
|---|---|---|---|
| 완전5도 | `2^(7/12)` | `3/2` | **−1.96 cents** (거의 완벽) |
| **장3도** | `2^(4/12)` | `5/4` | **+13.69 cents** ← 크게 어긋남 |
| **단3도** | `2^(3/12)` | `6/5` | **−15.64 cents** ← 더 어긋남 |

즉 **우리가 매일 듣는 3도는 전부 어긋나 있습니다.** 5도만 맞아요.

```javascript
// 패드 한 겹만 순정률 4:5:6으로 튜닝 — 맥놀이가 사라지고 "잠긴" 소리가 난다
function justChord(rootMidi, quality = 'minor') {
  const f = midiToFreq(rootMidi);
  return quality === 'minor'
    ? [f, f * 6/5, f * 3/2]      // 단3화음 10:12:15
    : [f, f * 5/4, f * 3/2];     // 장3화음 4:5:6
}

// 평균율 리드 + 순정률 패드를 겹치면
// 3도에서 13.7 cents 차이가 나면서 아주 느린 코러스가 자연 발생한다
```

> **왜 신선한가** — 신스 플러그인 대부분이 12-EDO에 고정돼 있어서, 이 사운드는 EDM에서 거의 안 들립니다.
> 패드가 "제자리에 딱 앉는" 느낌이 나고, 그 위의 평균율 리드와의 미세한 차이가
> 인위적인 디튠보다 훨씬 유기적인 두께를 만듭니다.

### 5. 배음을 하나씩 켜는 빌드업

**원문 근거** (§음색과 배음):
> 배음렬은 기본 주파수의 정수배(1x, 2x, 3x, 4x, 5x…)로 생성된다.
> 사인 = 단일 주파수 / 사각 = 홀수 배음만(텅 빈) / 톱니 = 모든 배음(버징)

우리 렌더러는 이미 배음을 직접 합성하고 있으므로 **배음 개수를 시간의 함수로** 만들면 됩니다.

```javascript
// 로우패스 스윕이 아니라, 배음을 문자 그대로 한 개씩 추가하는 빌드업
const harmonicsAtBar = (bar) => Math.min(32, 1 + bar * 2);

// 더 재밌는 변형: 빌드업은 홀수 배음만(텅 빈 사각파 느낌) →
// 드롭 순간 짝수 배음이 한꺼번에 들어오며 톱니로 변한다
function morphSaw(phase, f, cap, oddOnly) {
  let s = 0;
  const N = harmCount(f, cap);
  for (let n = 1; n <= N; n++) {
    if (oddOnly && n % 2 === 0) continue;
    s += Math.sin(n * phase) / n;
  }
  return s * (2 / Math.PI);
}
```

> **왜 신선한가** — 필터 스윕은 모두가 씁니다. 하지만 "홀수 배음 → 전 배음" 전환은
> 필터로는 만들 수 없는 소리입니다. 음정은 그대로인데 **악기가 바뀌는** 것처럼 들립니다.

### 6. 디튠 값을 아무 숫자나 쓰지 않기

**원문 근거** (§피타고라스 콤마):
> `(3/2)^12 / 2^7 = 1.0136` — 23센트의 간극. `3^n`은 결코 `2^(n+m)`이 될 수 없다.

검증: **23.46 cents.**

```javascript
// 현재: [-14, -5, 0, 5, 14]  ← 임의로 고른 값
// 대안: 피타고라스 콤마를 기준으로
const COMMA = 1200 * Math.log2((1.5 ** 12) / (2 ** 7));  // 23.46
const detune = [-COMMA, -COMMA/2, 0, COMMA/2, COMMA];
```

> 음악적으로 극적인 차이는 아니지만, 이 곡의 모든 숫자가 유도된 값이 됩니다.
> 원문의 마지막 문장 — *"모든 숫자가 우리가 유도한 무언가를 의미한다"* — 과 맞아떨어지죠.

## Tier 3 — 구조

### 7. 전조 = 상수 덧셈

**원문 근거** (§조성):
> 로마숫자는 상대 주소 지정 — 조를 옮기는 것은 **상수 덧셈**일 뿐이다.

```javascript
// 마지막 드롭을 단3도 위로 (+3) — 로마숫자는 그대로다
const transpose = (bar) => (bar >= 48 ? 3 : 0);
const chordAt = (bar) => chord(progression[bar % 4]).map((n) => n + transpose(bar));
```

+1(반음)은 흔한 "트럭 운전사 전조"라 촌스럽고, **+3(단3도)** 이나 **+5(4도)** 가 자연스럽습니다.
어차피 `.map(n => n + k)` 한 줄입니다.

### 8. 코드 생성 함수를 일반화

**원문 근거**: 3화음은 스케일 위에서 `[0, 2, 4]`, 즉 한 칸 건너뛰기(3도 쌓기).

인덱스 패턴만 바꾸면 다른 화성 세계가 열립니다:

```javascript
const chordAs = (degree, shape) =>
  shape.map((step) => {
    const i = degree - 1 + step;
    return scale[i % 7] + Math.floor(i / 7) * 12;
  });

chordAs(1, [0, 2, 4]);        // 3화음        — 현재
chordAs(1, [0, 2, 4, 6]);     // 7화음        — 감정 추가
chordAs(1, [0, 2, 4, 6, 8]);  // 9화음        — 넓고 몽환적
chordAs(1, [0, 3, 6]);        // 4도 쌓기     — 모호하고 현대적 ★
chordAs(1, [0, 1, 4]);        // 2도 포함     — 긴장감 있는 클러스터
chordAs(1, [0, 4]);           // 3음 생략     — 장/단 미정, 드롭에 적합 ★
```

★ 두 개를 추천합니다. **4도 쌓기**는 장/단이 흐려져 세련되게 들리고,
**3음 생략(파워코드)** 은 드롭에서 리드가 장/단을 결정하게 만들어 공간을 비워줍니다.

### 9. vii° — "부서진" 소리를 의도적으로

**원문 근거**:
> I로 끝나면 완결, V로 끝나면 계속될 것 같고, **vii°로 끝나면 부서진 느낌이 난다.**
> 감3화음 `[0, 3, 6]`은 불안한 소리.

브레이크다운 직전 한 마디를 vii°(= B dim `[59, 62, 65]`)로 두면 바닥이 꺼지는 느낌이 납니다.
드럼을 동시에 빼면 효과가 배가됩니다.

### 10. (실험) 19분할 브레이크다운

**원문 근거**: 5부터 25까지 분할을 전부 테스트해보면, 12가 5도를 0.1% 오차로 맞추는 첫 분할이다.

12만 답인 건 아닙니다. 검증한 19-EDO:

| | 12-EDO | 19-EDO |
|---|---|---|
| 5도 오차 | −1.96 cents | −7.22 cents |
| **장3도 오차** | **+13.69 cents** | **−7.37 cents** ← 더 정확 |

19-EDO는 5도를 조금 희생하는 대신 **3도가 훨씬 순정에 가깝습니다.**

```javascript
const edo = (n) => (step, ref = 440) => ref * 2 ** (step / n);
const f19 = edo(19);
// 19-EDO 단3화음: 0, 5, 11 스텝
```

> 곡 전체에 쓰면 이상하게 들리지만, **8마디 브레이크다운 패드에만** 쓰면
> "익숙한데 어딘가 다른" 이질감이 생깁니다. 원문이 던진 "왜 하필 12인가"라는 질문을
> 곡 안에서 직접 되묻는 셈이죠.
